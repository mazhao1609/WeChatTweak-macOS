## 本机样本

- 应用版本：4.1.15，WeChatBundleVersion 4.1.15.20，CFBundleVersion 270100。
- 核心库：`Contents/Resources/wechat.dylib`，arm64 UUID `0B9929BB-E55E-3513-B439-32375760BCA2`。
- 主程序只负责加载，旧的 `MessageService` Objective-C API 已不存在，不能直接移植旧版 swizzle。

## 静态分析依据

| 地址 | 用途 | 依据 |
| --- | --- | --- |
| `0x44541bc` | XML 消息分发 | `HandleNewXMLMsg` 字符串与 `revokemsg` 类型检查 |
| `0x30c5338` | 转换协议消息 | 构造 Message 后调用 `0x30c53b4` |
| `0x30c53b4` | 本次 hook 入口 | 调用替换原消息流程，再通知界面；返回 bool |
| `0x341738c` | 原生撤回替换流程 | `CoReplaceOriginMessageByRevoke` 日志与查询、构建系统消息、删除/更新分支 |
| `0x309675c` | 按会话及服务端 ID 查询 | 返回含有效标记的 Optional<Message> |
| `0xaa4484` / `0xaa46dc` | Message 构造 / 析构 | 原生系统消息分支使用的初始化与清理函数 |
| `0x4b6117c` / `0x4b64b60` | 设置消息类型 / 刷新扩展字段 | 原生 10000 类型系统消息构建顺序 |
| `0x30c5d58` | 新建本地消息 | 经 `0x31af50c` 设置自动分配本地 ID 标志，返回 Message |
| `0x305d158` | 新增消息通知 | 原生新增路径 `0x30d0a1c` 在取得非零本地 ID 后调用，发布新增消息事件 |
| `0x4518fe8` | 当前账号服务 | 虚表偏移 `0x28` 返回当前账号 std::string 引用 |

Message 大小 `0x278`；Optional<Message> 大小 `0x280`，有效标记位于 `0x278`。
arm64 的大结构体返回使用 x8 隐式返回地址。桥接结构保持 8 字节对齐，字符串采用当前 Apple libc++ 的 24 字节布局。

| Message 偏移 | 字段 |
| --- | --- |
| `0x0c` | 消息类型 |
| `0x18` / `0x30` | 发送方 / 接收方字符串 |
| `0xf4` / `0xf8` | 本地 ID / 服务端 ID |
| `0x100` | 毫秒排序时间；原生构造函数默认用秒级时间乘 1000 |
| `0x114` / `0x118` / `0x128` | 时间 / 状态 / 排序相关字段 |
| `0x130` | 内容字符串 |

## 行为与边界

只解析 `sysmsg[type=revokemsg]/revokemsg`，优先使用 `newmsgid`（缺失时兼容 `msgid`）查询原消息；群聊查询失败时再尝试撤回消息对象中的会话字段。没有原消息、非撤回协议或自己撤回才交回原函数；群聊对方消息也走保留流程。
收到的原消息不进入 `CoReplaceOriginMessageByRevoke`，独立创建 10000 类型系统消息并通知界面。
新提示使用撤回事件自己的服务端 ID，避免覆盖原消息；插入失败也不执行原删除流程。
仅返回独立非零本地 ID、10000 类型及匹配正文时发布新增事件，防止将已有原消息再次推入界面。
账户、会话、原消息 ID 共同组成去重键，不持久化消息正文；入库失败也不自动重试同一事件。
系统通知独立于提示入库，前台仅为插件通知启用横幅，其他通知回调转发给微信原代理。

## 首轮实测问题修复

首轮用户反馈无提示、无通知并出现重复消息。13:32 与 13:33 的系统日志中，插件调用点
`0x41d8` 对应“提示插入失败”分支；内存映射确认运行时插件已加载。

之前把 `0x30c5ddc` 误认为适合新建消息的接口。它经 `0x31b0d2c` 向 `0x31af548` 传入 `w3=0`，
最终在 `0x31762e8` 的标志检查处跳过从数据库回填本地 ID，无法给本地 ID 为 0 的新提示正确分配标识。
改用 `0x30c5d58 -> 0x31af50c` 后，该标志为 1，成功插入后在 `0x3176304` 写回生成的本地 ID。
这两个入口均走 AddMessage 流程，不能简单区分成“插入”和“更新”。

同时补齐 `0x100` 毫秒排序时间，并把 `OnMessageRevoke (0x30aa100)` 换成新增消息通知。
前者服务于原消息替换，并非新建本地提示的通知入口。不会自动清理首轮测试已产生的聊天记录。

安装和运行时均核对 UUID 及所需函数的前 16 字节。偏移配置仅适用于此样本，不能通过改版本号宣称支持新版本。
用户已确认修正后的防撤回正常；尚未逐项覆盖全部会话和通知场景。

## 小程序启动崩溃修复

用户随后反馈小程序等功能打不开。`WeChatAppEx` 与 `WeChatHelper` 的崩溃报告均停在
`_libsecinit_appsandbox`，标记为 `SYSCALL_SET_USERLAND_PROFILE`。
对比原版备份确认，安装器的 `codesign --force --deep --entitlements` 把主微信的权限覆盖到了子组件，
丢失了原有的 `com.apple.security.inherit`，并错误携带主微信的 application-identifier。
子组件自身的 Bundle ID 没有变化。

安装器改为只签名注入的动态库和修改的主应用，保留嵌套组件原厂签名及权限；
`--deep` 仅用于最终签名验证。已安装旧版必须先 `restore`，再用修正后的安装器 `patch`。
配置文件同时从 `Contents/Frameworks` 移到 `Contents/Resources`，运行时同步读取新路径，
避免签名工具将 JSON 当作嵌套代码。此修复不改动防撤回消息处理逻辑。
